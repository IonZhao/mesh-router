Architecture at a glance

Two decisions, two owners: the client decides geography (China vs. abroad), the VPS decides trust (residential vs. datacenter). The Mac mini decides nothing.

0 Shopping list & prerequisites

Get these before touching any config. Total recurring cost ≈ VPS ($10–20/mo) + domain (~$10/yr); Tailscale + Mac mini you already have.

Tip: clone the repo locally first — git clone <repo> && cd cross-border-net — every command below assumes you're inside it.

1 Buy & configure the domain

You said you don't have one yet — here's the full path. The domain is needed so Hysteria2 can get a real TLS certificate automatically. Reality (port 443) does not use it.

1a. Register a domain

Any registrar works. Cloudflare Registrar is recommended because it's at-cost (~$10/yr, no markup), gives you free DNS, and lets you add the optional CDN fallback path later.

  • Go to dash.cloudflare.com → Domain Registration → Register Domains.
  • Search a cheap TLD (.com, .net, or budget ones like .xyz). Avoid free domains — they're unreliable.
  • Buy it. The domain's DNS is now managed in Cloudflare automatically.
Already have a registrar (Namecheap/Porkbun/GoDaddy)? Fine — either use their DNS panel for step 1b, or point the nameservers at Cloudflare (Cloudflare → Add a site → it tells you which NS to set at your registrar).

1b. Point a subdomain at your VPS

Once you have the VPS's public IP (from your VPS provider's dashboard), create an A record:

TypeNameContentProxy status
Aproxyyour VPS IP, e.g. 203.0.113.45DNS only (grey cloud)
Critical: set proxy status to DNS only / grey cloud, NOT proxied/orange. Hysteria2 is UDP, and Cloudflare's proxy doesn't pass arbitrary UDP — orange cloud would break it. (The orange cloud is only for the optional CDN-over-WebSocket fallback, which is a separate record.)

This gives you proxy.yourdomain.com → your VPS. That hostname is your PROXY_DOMAIN.

2 Tailscale: account & two auth keys

Tailscale is the private link between VPS and Mac, and your out-of-band rescue channel. You need two auth keys (one per machine).

  1. Open Tailscale admin → Settings → Keys.
  2. Click Generate auth key. Enable Reusable off (one-time is fine), set a description like "tokyo-vps". Copy the tskey-auth-... value.
  3. Generate a second key for "mac-mini-exit". Copy it too.
Enable Tailscale SSH (admin → Settings, or per-key) so you can rescue the Mac mini even when the proxy path is dead — this is the whole point of having it as an out-of-band channel.

3 Generate secrets

Run once on your laptop (needs Docker). This creates UUIDs, the Reality keypair, and passwords, and writes secrets/vps.env + secrets/mac.env.

scripts/gen-secrets.sh

Then open secrets/vps.env and fill in the human fields:

FieldValue
PROXY_DOMAINproxy.yourdomain.com (from Phase 1)
ACME_EMAILyour email (Let's Encrypt notices)
REALITY_HANDSHAKEwww.microsoft.com (a TLS1.3 site to impersonate; the default is fine)
VPS_HOSTyour VPS public IP (Reality connects by IP)
TS_AUTHKEYauth key #1 from Phase 2
MAC_TAILSCALE_IPleave as placeholder — Phase 4 fills it

And in secrets/mac.env, set TS_AUTHKEY = auth key #2.

Encrypt for git (recommended): after editing, sops -e secrets/vps.env > secrets/vps.env.enc (same for mac.env). Keep these .enc files in a separate private repo (or your password manager) — NOT in this public repo. See .sops.yaml for the one-time age key setup, and the README's "Code delivery & disaster recovery".

4 Mac mini exit node

Do the Mac before the VPS — it prints its Tailscale IP, which the VPS needs. Run these on the Mac mini.

cd cross-border-net/mac-mini
./setup.sh

The script: installs sing-box + tailscale via brew, joins the tailnet, detects the Mac's Tailscale IP, renders the sing-box config, installs a LaunchDaemon (auto-starts at boot), and applies power settings. At the end it prints a line like:

MAC_TAILSCALE_IP=100.101.102.103

Copy that exact value into secrets/vps.env (replace the 100.x.y.z placeholder).

Finish in System Settings (can't be fully scripted): Energy → enable "Start up automatically after power failure" and "Prevent automatic sleeping"; and defer macOS automatic updates to a manual window so an OS update doesn't silently reboot your exit at 3am.

5 VPS stack

Run on the VPS. First install Docker if it's a fresh machine.

5a. Install Docker (skip if present)

curl -fsSL https://get.docker.com | sudo sh
sudo apt-get install -y gettext-base   # provides envsubst

5b. Bootstrap

Get the code + secrets onto the VPS via git: clone the public repo, then clone your private secrets repo into secrets/ (or restore your sops .enc files there). With the age key present, bootstrap.sh auto-decrypts. Then:

cd cross-border-net/vps
./bootstrap.sh

It validates secrets, renders config.json, checks it with sing-box check, and starts the stack. Confirm Tailscale joined:

docker exec tailscale tailscale status
Hysteria2 cert: on first start sing-box requests a Let's Encrypt cert over port 80 (HTTP-01). It needs proxy.yourdomain.com to resolve to this VPS and port 80 reachable (the firewall in Phase 6 allows it). If the cert fails, check the sing-box logs: docker logs sing-box.

6 Firewall

Lock down everything except the proxy ports. Run on the VPS.

sudo cross-border-net/scripts/firewall.sh

After this, only 443/tcp, 8443/udp, 80/tcp (ACME), and 22/tcp (SSH) are public. The dashboards (9090/19999/3001/8685) are reachable only over Tailscale.

7 Client config

Render the Clash Meta config (on any machine with the secrets), then import it into your China-side client.

cd cross-border-net/client
./render-client-config.sh   # writes clash-meta.yaml

Import clash-meta.yaml into a Clash Meta / mihomo client:

  • Windows/macOS: Clash Verge Rev, or mihomo Party, or FlClash.
  • iOS: Stash / Shadowrocket (support Reality + Hysteria2).
  • Android: FlClash / ClashMetaForAndroid.
How it routes: the client sends CN traffic direct and everything else to the VPS via a url-test group (Reality primary, Hysteria2 backup — automatic failover). It does not decide which exit a site uses; the VPS does.

8 Verify it works

Open the dashboard over Tailscale (use the VPS's Tailscale IP — tailscale ip -4 on the VPS):

http://<vps-tailscale-ip>:9090/ui

The secret is your CLASH_API_SECRET (in secrets/vps.env).

Checks

Switching exit modes (no redeploy)

Mode A = residential (Mac mini). Mode B = VPS-direct (if your VPS has a clean native IP, or the Mac is offline for a while). Route rules never change — you just pick a selector member in the dashboard.

MemberBehaviourWhen
mac-auto defaultprefer Mac mini, auto fail-open to VPS direct if downnormal operation
mac-outpin to Mac mini, fail closedstrict IP purity
directVPS's own IPMode B

In metacubexd → Proxies → group trusted-exit → click a member. Instant, persists across restarts. For a permanent default change, also edit "default" in vps/sing-box/config.json.template and re-run bootstrap.sh. In Mode B the Mac tunnel + monitoring stay running, just unused.

Runbooks

VPS IP got blocked (most likely disaster — target < 30 min)
  1. Provision a new VPS (or request an IP swap from the provider).
  2. Get the repo + secrets onto it and run vps/bootstrap.sh.
  3. Update the DNS A record proxy.yourdomain.com → new IP, and VPS_HOST in secrets/vps.env.
  4. Re-render the client config (client/render-client-config.sh) and re-import. Reality reconnects by IP.

Insurance against this: the optional Cloudflare CDN-over-WebSocket path (design doc §4.1) survives IP blocking entirely.

Mac mini went down
  • You're not offline — mac-auto already failed sensitive traffic over to the VPS direct exit (Uptime Kuma should have alerted you).
  • SSH in over Tailscale (works even with the data path dead): ssh you@mac-mini-exit.
  • Re-run mac-mini/setup.sh to rebuild. Inspect the daemon: sudo launchctl print system/com.crossborder.singbox | grep state and logs at ~/Library/Logs/cross-border-net/.
Rotate secrets

Re-run scripts/gen-secrets.sh (regenerates random values), re-encrypt with sops, then re-run bootstrap.sh on the VPS and setup.sh on the Mac, and re-render the client config. Changing MAC_VLESS_UUID requires updating both ends (it's shared).

Troubleshooting

SymptomLikely cause / fix
Hysteria2 won't get a certproxy.yourdomain.com not resolving to the VPS, or port 80 blocked. Check nslookup + firewall + docker logs sing-box.
Client connects but no sites loadReality params mismatch. Verify the client's public-key/short-id/servername match the VPS. Re-render the client config.
Claude/OpenAI show Tokyo IP, not USYou're in Mode B or the Mac is down → fail-open kicked in. Check the trusted-exit selector + Uptime Kuma.
Slow / high latency to US sitesTailscale on DERP relay (run the status check), or poor VPS↔China route. Consider a US-West VPS (design doc §4.3).
Can't reach a dashboardYou must be on Tailscale and use the VPS's 100.x IP, not its public IP — the firewall blocks admin ports publicly.
sing-box check fails after a version bumpConfig schema changed (esp. DNS in 1.12+). Pin SINGBOX_VERSION back to v1.11.x in .env or migrate the config.
